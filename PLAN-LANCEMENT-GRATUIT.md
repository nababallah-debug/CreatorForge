# Plan de lancement gratuit CreatorForge — 30 jours

Objectif : vérifier si des créateurs Roblox utilisent les outils et quelles fonctions méritent d'être développées. L'objectif n'est pas de promettre un revenu.

## Semaine 1 — fiabilité

- [ ] Installer les dépendances et lancer `npm run dev`.
- [ ] Exécuter `npm run typecheck`, `npm run lint`, `npm run build` et corriger les erreurs.
- [ ] Tester le calculateur avec 3 exemples manuels, ainsi que les exports.
- [ ] Vérifier les menus sur mobile, les liens et la page `/pricing`.
- [ ] Retirer toute formulation qui laisse croire qu'une vraie IA, des comptes ou des paiements sont déjà actifs.

## Semaine 2 — démonstration

Publier 3 petites démonstrations :

1. « Équilibrer les prix d'un tycoon Roblox en 60 secondes » — utiliser le calculateur.
2. « 3 idées de jeux Roblox à prototyper » — montrer le générateur de concepts, en précisant qu'il est local/règle-based.
3. « Organiser un projet Roblox avant de coder » — montrer le plan de développement.

Chaque vidéo doit renvoyer vers le site et demander une action précise : tester un outil, signaler un bug ou suggérer une fonctionnalité. Éviter les faux chiffres de revenus et les promesses de viralité.

## Semaine 3 — tests utilisateurs

- [ ] Trouver 5 à 10 testeurs dans des communautés où l'auto-promotion est autorisée.
- [ ] Demander à chaque testeur d'effectuer une tâche concrète.
- [ ] Noter les problèmes rencontrés et le temps nécessaire pour terminer la tâche.
- [ ] Demander quelle fonction lui ferait gagner le plus de temps, et si elle justifierait un paiement. Ne pas collecter d'informations sensibles.

## Semaine 4 — choisir la suite

- [ ] Corriger les 3 problèmes les plus fréquents.
- [ ] Repérer l'outil le plus utilisé.
- [ ] Garder un tableau simple : visites approximatives, testeurs, retours, demandes répétées.
- [ ] Ne commencer le premium que si une demande revient plusieurs fois et que le coût de fonctionnement est compris.

## Critères de décision

- Peu de testeurs : améliorer la démonstration et la distribution avant d'ajouter des fonctions.
- Des visites mais peu d'utilisation : clarifier la proposition de valeur et simplifier l'outil principal.
- Usage répété et demandes convergentes : développer une seule fonction premium, puis la tester avant de choisir un prix définitif.

## Budget

- Développement : outils déjà installés et logiciels gratuits.
- Hébergement : plan gratuit compatible avec l'application.
- Domaine : ne pas acheter de domaine au départ.
- IA distante : ne pas appeler une API payante sans budget/plafond et surveillance. Utiliser les générateurs locaux existants pendant la validation.
- Paiements : ne pas activer avant validation par le représentant légal et vérification des obligations applicables.
